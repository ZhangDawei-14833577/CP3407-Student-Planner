# Initial Product Backlog

## Project

Student Assignment and Study Planner

## Purpose

This document contains the initial backlog ideas produced during the
project initiation stage.

These user stories are preliminary. They will be reviewed and refined
after interviews with target users.

## Initial User Stories

### US-01: User Registration

As a university student, I want to create an account so that I can
securely store and access my academic planning information.

### US-02: User Login and Logout

As a registered student, I want to log in and log out so that my
academic data remains private and secure.

### US-03: Add a Course

As a student, I want to add a course so that I can organise assessments
and study tasks according to each subject.

### US-04: Manage Courses

As a student, I want to view, edit and delete my courses so that my
course information remains accurate.

### US-05: Add an Assessment

As a student, I want to add an assignment or examination with a due
date so that I can monitor upcoming academic deadlines.

### US-06: Manage Assessments

As a student, I want to view, edit and delete assessment information so
that changes to my academic schedule can be recorded.

### US-07: Create a Study Task

As a student, I want to create a study task associated with a course or
assessment so that I can divide academic work into manageable actions.

### US-08: Prioritise and Complete Tasks

As a student, I want to assign priorities and update task completion
status so that I can focus on important unfinished work.

### US-09: Search, Filter and Sort Tasks

As a student, I want to search, filter and sort tasks by course,
priority, status and due date so that I can quickly find relevant work.

### US-10: View a Dashboard

As a student, I want to view a dashboard showing upcoming, overdue and
completed work so that I can understand my current academic workload.

## Next Requirements Activity

The next stage will involve interviewing target university students.

Feedback from the interviews will be used to:

- Confirm whether the proposed features are useful
- Identify missing requirements
- Remove unnecessary requirements
- Refine the user-story descriptions
- Assign priorities
- Estimate implementation effort
